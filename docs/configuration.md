# Instance configuration

[Documentation](./README.md) · **English** · [简体中文](./zh-CN/configuration.md)

Configure the running instance in **Settings → System Settings** (`/admin/settings`). Only administrators can access this page. Settings are stored in SQLite; environment files are mainly for infrastructure overrides.

## First run

A fresh database opens `/setup`. Set the public site URL, mail domain and first administrator account. The administrator password must have at least 12 characters. Existing installations with users keep their accounts and do not run setup again.

Use the final HTTPS address, such as `https://mail.example.com`, as the site URL. The site URL is used for redirects and OAuth metadata; changing it also means reviewing registered callback URLs and reverse-proxy settings.

## Find the right control

| Settings area | What belongs here | Guide |
| --- | --- | --- |
| **System Settings → Site** | Public site URL, extra allowed CORS origins, optional SSO login page URL | [Shared-session SSO](./sso.md) |
| **System Settings → Mail** | Mail domain used when creating addresses | [Mail and DNS](./mail.md) |
| **System Settings → SMTP relay** | Relay host, port, username and password | [Outbound delivery](./mail.md#sending) |
| **System Settings → Bot protection** | Optional Cloudflare Turnstile site key and secret | See below |
| **System Settings → SSO / Session** | Cookie scope, lifetime and session rate limits | [Shared-session SSO](./sso.md) |
| **Sign-in providers** | External services used to sign in to HostID | [Third-party login](./oauth.md#third-party-login) |
| **App access** | OAuth client apps that use HostID as their provider | [OAuth 2.0](./oauth.md) |
| **Database** | Administrative inspection of stored records | Use with care; prefer the dedicated settings and app forms for changes |

Most settings apply immediately after saving. The SMTP greeting includes the mail domain captured at startup; restart the service to update that greeting. Changing the mail domain does not rewrite existing users' email addresses.

Secret fields return masked values. Leave a secret field empty to keep its current value; use its explicit clear control to remove it. Keep the database and encryption keys together when [backing up](./docker.md#backup-and-restore).

## Optional Turnstile

Set both the site key and secret in **Bot protection**, and configure the permitted hostnames in your Turnstile account. The public site key is served through `/config.js`; the secret stays on the backend. Container deployments do not need a frontend rebuild for a key change.

When developing with Vite, `/config.js` is also generated by the dev-server middleware from `frontend/.env`; see the [development guide](./development.md#local-configuration).

## Infrastructure overrides

Docker defaults are already provided by the Compose files. Use the optional `hostid.env` file for the all-in-one deployment, or `backend.env` for the published two-container deployment. For source Compose, the optional file is `backend/.env`.

| Variable | Purpose |
| --- | --- |
| `DATABASE_URL` | Prisma SQLite URL; containers set an absolute path such as `file:/app/data/prod.db` |
| `HOSTID_DATA_DIR` | Directory holding `secrets.json`; otherwise derived from the database location |
| `JWT_SECRET` | Optional signing-secret override, at least 32 characters |
| `DATA_ENCRYPTION_KEY` | Optional data-encryption-secret override, at least 32 characters |
| `PORT` / `SMTP_PORT` | Application listeners; shipped Compose files set their internal values explicitly |
| `HOSTID_WEB_ROOT` | Built frontend directory served by the all-in-one backend |

Host port mappings and image selection are **Compose variables**, read from the shell or the deployment directory's `.env`: `FRONTEND_PORT`, `BACKEND_PORT`, `BACKEND_BIND_ADDRESS`, `SMTP_PORT`, `IMAGE_TAG`. An application `env_file` does not set Compose port interpolation. See [port configuration](./docker.md#ports).

In local development, explicitly set `DATABASE_URL`; the example file leaves it commented out. See [`backend/.env.example`](../backend/.env.example) for optional overrides. Avoid changing secret overrides without planning for existing encrypted settings and sessions, and preserve the actual overridden values in your backup.

## Existing installations

Legacy site, mail, relay, Turnstile and SSO environment values are imported when their setting is first missing from the database. Once saved there, change them through System Settings. An environment-file edit does not override a setting already stored in the database.

External OAuth providers are configured through **Sign-in providers**; old GitHub-specific OAuth environment variables are no longer read. See [upgrade notes](./docker.md#upgrading) before changing an existing deployment.
